--------------------------------------------------------------------------------
7. MINOR OBSERVATIONS (non-blocking, do NOT change verdict)
--------------------------------------------------------------------------------
(a) normalizeResponsesFromObjects (L256-260) is a stub that always returns
    null. This is deliberate and correct: Responses API uses SSE event
    framing, never raw NDJSON, so the NDJSON branch for this family should
    refuse. The "void objects" silences the unused-param lint cleanly.
    Not a defect; documenting for completeness.

(b) Anthropic content_block_start with no subsequent content_block_delta
    produces an empty text block (text:""). This matches Anthropic's own
    SDK semantics (empty text block is valid). Acceptable.

(c) OpenAI Chat: when delta.content is absent but delta.role is present
    (first chunk), content remains "" until later chunks arrive. If the
    stream terminates after only a role chunk with finish_reason="stop",
    the merged choice will have content:"". This is correct behavior (the
    upstream genuinely sent no content); not a normalizer bug.

(d) Gemini complete-object preference loop (L501-514) walks the typed[]
    array from the END backwards, returning the LATEST coherent candidate
    object. This is intentional: terminal generateContent responses carry
    the most complete state. Comment at L497-500 explains the role-gate.
    Correct.

(e) The synthesis path for Gemini ignores functionCall / inlineData parts
    (only text parts are concatenated at L540-548). For tool-calling
    Gemini streams, synthesis will produce text:"" and refuse (textParts
    empty -> null at L569). This is SAFE (refusal beats fabrication) but
    means tool-call-only Gemini streams fall back to raw-text tracing.
    Acceptable for an observability normalizer; flagged for future
    enhancement only.

(f) No emoji in code, comments, or string literals (AGENTS.md rule
    satisfied). Biome formatting appears consistent (double quotes,
    trailing commas, 2-space indent, ~100 char width).


--------------------------------------------------------------------------------
8. ROBUSTNESS / REFUSAL DISCIPLINE  ->  PASS
--------------------------------------------------------------------------------
The module's contract (L39-48) states it MUST NOT fabricate a completed
structured object for streams that did not reach a terminal payload. Every
family honors this:

  Responses:   null if response.failed/incomplete, or no created base,
               or no usable output text.
  Anthropic:   null if no message_start base OR no message_stop.
  OpenAI Chat: null if no choice ever carried finish_reason.
  Gemini:      null if no candidates, or no textParts, or no finishReason.

Every "I don't have a trustworthy terminal signal" case returns null,
forcing the caller (response-handler.ts emit site) to pass responseOutput
as null/undefined, which the Langfuse consumer handles by falling back to
responseText. Refusal discipline is uniform and correct.
